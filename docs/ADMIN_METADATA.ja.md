# 管理者メタデータと保存ビュー

## 対象範囲と識別子

メタデータは導入済みサイトと設定済み管理者に属します。公開コレクターはメタデータを受信・返却しません。現在の単一管理者設定は一方向の所有者キーで表現し、将来アカウントIDへ移行する場合も、孤立したビューを公開しない設計です。

| 概念 | `entity_type` | 安定キー |
|---|---|---|
| 組織 | `organization` | `AS`を除いた数値ASN |
| 匿名訪問者 | `visitor` | 既存の不透明な`visitor_id` |
| コンテンツ | `content` | 既存の保存済み正規化パス |
| 参照元ドメイン | `referrer` | 小文字に正規化したドメイン |
| キャンペーン | `campaign` | `source`、`medium`、`campaign`、`content`、`term`の順序付きJSON |
| 外部リンク先 | `external_target` | 小文字に正規化したリンク先ドメイン |

正規化キーのSHA-256を固定長の検索値として保存し、表示用に元の正規化キーも保持します。一意性にはエンティティ種別とハッシュを使用します。SHA-256の衝突は計算上現実的でないものとして扱い、保持したキーにより想定外の不一致を確認できます。

コンテンツ注釈はリダイレクトやURL変更へ自動追従しません。保存済みパスに紐付き、孤立する場合があります。孤立した注釈もナレッジ画面で確認できます。似たタイトルだけでコンテンツを統合しません。

## 制限と動作

別名は任意のプレーンテキストで最大120 Unicode文字、メモは最大4,000 Unicode文字です。タグ名は大文字・小文字を区別せず最大50文字で一意とし、定義済みの見やすい色を選択できます。1エンティティ当たり50タグまでです。出力は常にエスケープします。タグ削除は割り当てだけを連動削除し、解析データを削除しません。

注目状態は数値ASNだけに適用します。MaxMind組織名、分類、セッション、イベント、Human/Bot、指標を変更せず、通知も送りません。ASNはIPアドレスの登録先ネットワーク組織を示しますが、閲覧者の勤務先や本人性を証明しません。

保存ビューはスキーマバージョン1と画面別キーを使用します。相対期間（`today`、`yesterday`、`7d`、`30d`）は読込時に画面側で再計算し、カスタム日付は絶対日付のままです。ピン留めと、所有者・画面ごとに1件の既定値を設定できます。未知のキー、型、日付、対象、並び順は拒否します。ページ番号、セッション・CSRF・認証状態、サイトトークン、認証情報、暗号鍵、復号IP、SQL、リクエストID、API応答は保存しません。

高負荷の解析画面へテキスト走査を追加しないため、メモ検索はナレッジ画面に限定します。

## スキーマと索引

新規導入とv0.6.1からの冪等更新で、次を作成します。

- `tya_annotations`：`(entity_type, entity_hash)`ごとに1行。管理・注目一覧用の`watched/type/updated`と`type/updated`索引。
- `tya_tags`：一意な`normalized_name`。
- `tya_annotation_tags`：主キー`(annotation_id, tag_id)`と逆方向の`(tag_id, annotation_id)`索引。外部キーの連動削除はメタデータだけに適用。
- `tya_saved_views`：所有者・画面、所有者・ピン、所有者・画面・既定値の索引。

正確なDDLは`app/schema.php`にある4個の`CREATE TABLE IF NOT EXISTS`文です。`SchemaMigrator`は既存v0.6.1イベント移行後に、更新用として同じ文を実行します。`tya_events`の変更や履歴書き換えは行いません。

## 更新時に保持する内容

アプリケーション更新時は、`config.php`、`data/`、`storage/`、`storage/installed.lock`、DB・管理者認証情報、暗号化・HMAC鍵、サイトトークン、GeoLite2 City・ASN、言語設定、セッション、ログ、キャッシュ、すべての解析行を保持する必要があります。配布ZIPには保護設定付きの空`data/`・`storage/`を含めますが、実行時ファイルは含めません。

通知、見込み度算定、除外管理、エクスポート、保持期間管理、日次集計、外部情報付加はv0.6.2に含めません。
