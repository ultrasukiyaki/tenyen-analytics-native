# GeoLite2 automatic updates

Version 0.8.1 keeps GeoLite2 City and ASN independently healthy while retaining manual MMDB upload. Configure a MaxMind account ID and license key over the HTTPS administration screen. The key is encrypted with the installation encryption secret, stored with mode 0600 under protected `storage/`, masked in the UI, excluded from logs, JavaScript, and release packages, and never written to `config.php` during upgrades.

Run `php bin/geolite2-update.php scheduled` daily from a trusted host cron. Enabled installations download only when the weekly due time arrives. Failures use a six-hour exponential backoff capped at seven days. `status`, `run`, `city`, and `asn` provide bounded CLI maintenance. A non-blocking lock prevents overlap.

Downloads use a two-stage credential boundary. The first request uses Basic Authentication only with the fixed `download.maxmind.com/geoip/databases/GeoLite2-{City,ASN}/download?suffix=tar.gz` permalink and disables automatic redirects. A direct HTTP 200 archive is accepted. For 301, 302, 303, 307, or 308, every `Location` must be an absolute HTTPS URL on the exact source-controlled MaxMind R2 delivery host, without user-info, fragment, or a port other than 443. A fresh cURL handle with no authentication or cookies retrieves the signed artifact. Every additional hop is revalidated, with loop detection and a three-hop limit.

Signed URLs are transient secrets: neither the URL nor its query is logged, persisted, rendered, or returned as JSON. HTTP 401 identifies invalid credentials, 403 identifies unavailable product permission, 429 requests a later retry, and other failures expose only the numeric status. Network/TLS, redirect, size, archive, MMDB, and activation failures use bounded safe messages without response bodies, cURL traces, proxy details, filesystem paths, or secrets.

Response headers are limited to 64 KB and streamed archive bytes to 150 MB; the extracted MMDB is limited to 100 MB and archives to 200 entries. Absolute paths, traversal, links, devices, duplicates, missing expected MMDBs, corrupt databases, and wrong City/ASN types are rejected. The expected MMDB is copied to a protected 0600 temporary file in a 0700 directory, validated with the existing reader, staged beside the destination, and atomically renamed. The previous valid database is restored if activation fails. Request-specific files are cleaned in success and exception paths, and stale temporary files older than one day are removed.

Health tracks installed/readable state, configured path internally, safe filename, database type, build date, size, staleness after 45 days, last attempt/success, status, and safe errors separately for City and ASN. Filesystem paths and secrets are not returned to the browser. A City failure never disables ASN or vice versa.

Automatic updates require PHP cURL and outbound HTTPS. Manual chunked upload remains supported when automatic credentials or outbound access are unavailable. Upgrading from v0.8.0 changes no schema or indexes and preserves `config.php`, `data/`, `storage/`, `storage/installed.lock`, administrator and database credentials, encryption keys, site token, encrypted MaxMind credentials, MMDB files, analytics, aggregates, metadata, exclusions, saved views, and language preference. MMDB files, credentials, signed URLs, state, installation locks, configuration, analytics, and aggregates are never included in the release archive.
