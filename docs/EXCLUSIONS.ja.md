# 除外ルール

バージョン0.6.3では、収集除外と分析除外を分離しています。収集ルールは今後のリクエストだけに適用され、一致した場合は受付済みの応答を返しますが`tya_events`へ保存しません。分析ルールは一致イベントを保持したまま、`tya_event_exclusions`を通じてレポートから隠します。分析ルールを無効化または削除すると、保持済み履歴は再び表示されます。

## ルール種類と照合

IPv4・IPv6完全一致、IPv4・IPv6 CIDR、URIパス完全一致、URI前方一致、認証済みNative管理者セッション、Bot、国、地域、ASN、組織名部分一致、組織分類、ブラウザ、OS、端末、参照元ドメイン、UTM source・medium・campaignに対応します。URIはクエリ文字列を除いた正規化パスで照合します。文字列ディメンションは大文字・小文字を区別せず、組織名は大文字・小文字を区別しない部分一致です。利用者指定の正規表現や生SQLは受け付けません。

優先順位は、Native管理者、IP完全一致、CIDR、URI完全一致、URI前方一致、Bot、国、地域、ASN、組織、組織分類、ブラウザ、OS、端末、参照元ドメイン、UTM source、UTM medium、UTM campaignの順で固定です。診断画面には一致した全ルールと、勝者となるルール、優先順位、スコープ、動作、理由を表示します。

## 管理とプライバシー

ルールの一覧、作成、編集、無効化、診断、削除は認証済み管理コンソールだけで利用できます。書き込みと診断はすべてCSRF検証を必要とします。値とメモには上限があり、種類・スコープは許可リスト方式、SQLはプリペアド、出力は表示時にエスケープします。公開コレクターは一般的な除外結果だけを返し、ルール定義を公開しません。

既存の暗号化IPは、分析ルール保存時にサーバー内の制限付きバッチ照合でだけ復号します。レポートは索引付きのイベント・ルール照合結果をSQLで参照し、全件をPHPで復号・絞り込みしません。履歴イベントは削除しません。IP完全一致とCIDRはIPv4・IPv6の両方に対応します。

## 更新とスキーマ

冪等な更新で`tya_exclusion_rules`と`tya_event_exclusions`を追加します。有効状態・スコープ・優先順位検索とイベント・ルール結合用の索引を備えます。イベント表と既存の解析上の事実は変更しません。アプリケーションファイルの置換時は、`config.php`、`data/`、`storage/`、`storage/installed.lock`、認証情報、鍵、サイトトークン、MMDB、イベント、セッション、メタデータ、保存ビュー、言語設定を保持してください。
