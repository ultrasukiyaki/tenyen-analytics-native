# 日次集計と性能

バージョン0.7.1は、生ログ整理前に統計履歴を保持します。設定済みアプリケーション時間帯で完了した日だけを集計し、生イベントの事実は書き換えません。

## データモデル

`tya_daily_metrics`はHuman、Bot、全体について、PV、推定訪問者、セッション、直帰、入口・出口、カスタム・クリック・ダウンロード・404イベント、エンゲージメント・スクロールの合計と標本数を日別保存します。`tya_daily_dimensions`は日別上位のコンテンツ（200）、チャネル（50）、参照元（100）、キャンペーン（100）、国（250）、ASN・組織（100）、イベント（100）を保存します。`tya_aggregate_state`は期間チェックポイントと安全なエラー状態を保持します。日・対象および軸・日付用の主キー・範囲索引を追加し、本番相当`EXPLAIN`根拠なしに生イベント索引は追加しません。

セッションは最初のPVのローカル日に帰属します。直帰はPVが1件のセッションです。入口・出口は率でなく件数を保持します。エンゲージメントはセッション・パスごとの最大有効滞在時間と1～100のスクロール率を標本にします。平均は合計と標本数から算出します。複数日にまたがる訪問者数は日別推定値です。

## ジョブと復旧

信頼できるCLI cronから、`php bin/cleanup.php scheduled`より先に`php bin/aggregate.php incremental`を毎日実行します。1回の処理は最大31日です。復旧・補正には`resume`、`day YYYY-MM-DD`、`range FROM TO`を使います。日別再実行は1トランザクションで軸行を削除し対象行をupsertするため、合計を重複させません。差分実行は遅延エンゲージメントを含めるため直近完了日を再構築します。

認証・CSRF保護済みの保存画面でも、同じ制限付き操作と状態を確認できます。公開メンテナンスURLはありません。日付は厳密な`YYYY-MM-DD`、期間は730日までで、対象・軸は許可リスト、SQLはプリペアドです。エラーにSQL、パス、認証情報、トークン、復号IP、スタックトレースを含めません。

## 生ログ・集計境界と整理

ダッシュボードの日別・月別レポートは存在する集計日を1回だけ読み、欠けた日だけ生ログを問い合わせます。生ログのみ、集計のみ、混在の全範囲で重複しません。リアルタイム、アクセス履歴、訪問者・セッション詳細は生ログ専用です。

保持境界はローカル日0時へ合わせるため、最大1日弱を余分に保持します。cleanupは削除対象となる全ローカル日を`tya_daily_metrics`と照合し、不足時は削除を停止します。分析除外は集計時に反映します。除外ルール変更後は、生ログが残っている間に対象日を再構築してください。

更新前にバックアップし、`config.php`、`data/`、`storage/`、`storage/installed.lock`、認証情報、鍵、サイトトークン、MMDB、言語設定、イベント、セッション、注釈、タグ、除外、保存ビュー、ライフサイクル状態を保持してください。
